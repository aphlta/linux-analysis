### 2. 用户空间API定义 (arch/riscv/include/uapi/asm/kvm.h)

**新增结构体**:
```c
/* SBI STA extension registers for KVM_GET_ONE_REG and KVM_SET_ONE_REG */
struct kvm_riscv_sbi_sta {
    unsigned long shmem_lo;
    unsigned long shmem_hi;
};
```

**新增寄存器类型定义**:
```c
/* Registers for specific SBI extensions are mapped as type 10 */
#define KVM_REG_RISCV_SBI_STATE     (0x0a << KVM_REG_RISCV_TYPE_SHIFT)
#define KVM_REG_RISCV_SBI_STA       (0x0 << KVM_REG_RISCV_SUBTYPE_SHIFT)
#define KVM_REG_RISCV_SBI_STA_REG(name) \
        (offsetof(struct kvm_riscv_sbi_sta, name) / sizeof(unsigned long))
```

**设计原理**:
- 使用两个unsigned long寄存器(shmem_lo和shmem_hi)来表示64位的共享内存地址
- 在32位系统上，需要两个寄存器来组成完整的64位地址
- 在64位系统上，只使用shmem_lo，shmem_hi必须为0

### 3. 寄存器操作实现 (arch/riscv/kvm/vcpu_sbi_sta.c)

#### 3.1 寄存器读取函数

```c
int kvm_riscv_vcpu_get_reg_sbi_sta(struct kvm_vcpu *vcpu,
                                   unsigned long reg_num,
                                   unsigned long *reg_val)
{
    switch (reg_num) {
    case KVM_REG_RISCV_SBI_STA_REG(shmem_lo):
        *reg_val = (unsigned long)vcpu->arch.sta.shmem;
        break;
    case KVM_REG_RISCV_SBI_STA_REG(shmem_hi):
        if (IS_ENABLED(CONFIG_32BIT))
            *reg_val = upper_32_bits(vcpu->arch.sta.shmem);
        else
            *reg_val = 0;
        break;
    default:
        return -EINVAL;
    }
    return 0;
}
```

**核心逻辑**:
- `shmem_lo`: 返回共享内存地址的低32位（或在64位系统上的完整地址）
- `shmem_hi`: 在32位系统上返回高32位，在64位系统上返回0

#### 3.2 寄存器写入函数

```c
int kvm_riscv_vcpu_set_reg_sbi_sta(struct kvm_vcpu *vcpu,
                                   unsigned long reg_num,
                                   unsigned long reg_val)
{
    switch (reg_num) {
    case KVM_REG_RISCV_SBI_STA_REG(shmem_lo):
        if (IS_ENABLED(CONFIG_32BIT)) {
            gpa_t hi = upper_32_bits(vcpu->arch.sta.shmem);
            vcpu->arch.sta.shmem = reg_val;
            vcpu->arch.sta.shmem |= hi << 32;
        } else {
            vcpu->arch.sta.shmem = reg_val;
        }
        break;
    case KVM_REG_RISCV_SBI_STA_REG(shmem_hi):
        if (IS_ENABLED(CONFIG_32BIT)) {
            gpa_t lo = lower_32_bits(vcpu->arch.sta.shmem);
            vcpu->arch.sta.shmem = ((gpa_t)reg_val << 32);
            vcpu->arch.sta.shmem |= lo;
        } else if (reg_val != 0) {
            return -EINVAL;
        }
        break;
    default:
        return -EINVAL;
    }
    return 0;
}
```

**核心逻辑**:
- **32位系统**: 需要正确处理64位地址的高低位组合
- **64位系统**: 只允许设置shmem_lo，shmem_hi必须为0
- **错误处理**: 在64位系统上如果尝试设置非零的shmem_hi值，返回-EINVAL

## 技术原理分析

### 1. Steal-Time机制

Steal-time是虚拟化环境中的一个重要概念：
- **定义**: 指虚拟CPU应该运行但实际被hypervisor调度给其他任务的时间
- **用途**: 帮助guest OS了解其真实的CPU使用情况，进行更准确的时间计算和性能分析
- **实现**: 通过共享内存区域在hypervisor和guest之间传递steal-time信息

### 2. 共享内存地址管理

**地址存储结构**:
```c
/* SBI steal-time accounting */
struct {
    gpa_t shmem;      // Guest物理地址
    u64 last_steal;   // 上次记录的steal时间
} sta;
```

**地址处理策略**:
- 使用`gpa_t`类型存储guest物理地址
- 在32位和64位系统上采用不同的处理方式
- 通过寄存器接口暴露给用户空间进行状态保存/恢复

### 3. 32位/64位兼容性设计

**设计考虑**:
- **32位系统**: 需要两个32位寄存器组成64位地址
- **64位系统**: 只使用一个寄存器，另一个必须为0
- **向后兼容**: 64位用户空间可以忽略hi寄存器的保存/恢复
