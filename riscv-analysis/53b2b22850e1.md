## 提交描述

正如Palmer所说，hwprobe现在"算是自己的一个东西了，而且只会变得更大..."。这个提交将hwprobe系统调用从sys_riscv.c文件中移动到一个独立的文件sys_hwprobe.c中。

```
 3 files changed, 290 insertions(+), 285 deletions(-)
```

## 详细修改内容分析

### 1. Makefile修改

在`arch/riscv/kernel/Makefile`中添加了新的编译目标：
```makefile
+obj-y  += sys_hwprobe.o
```

### 2. 新文件创建：sys_hwprobe.c

创建了一个全新的文件`arch/riscv/kernel/sys_hwprobe.c`，包含289行代码，主要包括：

#### 头文件包含
```c
#include <linux/syscalls.h>
#include <asm/cacheflush.h>
#include <asm/cpufeature.h>
#include <asm/hwprobe.h>
#include <asm/processor.h>
#include <asm/delay.h>
#include <asm/sbi.h>
#include <asm/switch_to.h>
#include <asm/uaccess.h>
#include <asm/unistd.h>
#include <asm/vector.h>
#include <asm/vendor_extensions/thead_hwprobe.h>
#include <vdso/vsyscall.h>
```

#### 核心功能函数

1. **hwprobe_arch_id()**: 探测架构ID信息
   - 支持MVENDORID、MIMPID、MARCHID的查询
   - 处理多CPU环境下的一致性检查

2. **hwprobe_isa_ext0()**: 探测ISA扩展信息
   - 检测基础扩展：FPU、压缩指令、向量扩展
   - 支持大量的RISC-V扩展检测，包括：
     - 原子操作扩展：ZAAMO、ZACAS、ZALRSC、ZAWRS
     - 位操作扩展：ZBA、ZBB、ZBC、ZBKB、ZBKC、ZBKX、ZBS
     - 压缩指令扩展：ZCA、ZCB
     - 缓存管理扩展：ZICBOM、ZICBOZ
     - 条件操作扩展：ZICOND
     - 加密扩展：ZKND、ZKNE、ZKNH、ZKSED、ZKSH、ZKT
     - 向量扩展：ZVBB、ZVBC、ZVE32F、ZVE32X、ZVE64D、ZVE64F、ZVE64X等

3. **hwprobe_misaligned()**: 探测非对齐访问性能

4. **hwprobe_one_pair()**: 处理单个探测请求

5. **do_riscv_hwprobe()**: 主要的hwprobe实现函数

6. **SYSCALL_DEFINE5(riscv_hwprobe)**: 系统调用入口点

#### vDSO支持

包含了vDSO（虚拟动态共享对象）的初始化代码：
```c
#ifdef CONFIG_MMU
static int __init init_hwprobe_vdso_data(void)
{
    // 初始化vDSO数据，为"所有CPU"的情况提供答案
    // 在常见情况下节省系统调用
}
arch_initcall_sync(init_hwprobe_vdso_data);
#endif
```

### 3. sys_riscv.c文件简化

从`arch/riscv/kernel/sys_riscv.c`中移除了285行hwprobe相关代码，现在该文件只保留：
- mmap系统调用实现
- riscv_flush_icache系统调用实现
- __riscv_sys_ni_syscall函数

## 代码修改原理

### 1. 模块化设计原则

这个重构遵循了软件工程中的**单一职责原则**和**模块化设计**：
- **分离关注点**: hwprobe功能专注于硬件特性探测，与其他系统调用功能分离
- **可维护性**: 独立文件便于hwprobe功能的维护和扩展
- **代码组织**: 避免sys_riscv.c文件过于庞大

### 2. 功能完整性保持

重构过程中保持了hwprobe功能的完整性：
- 所有原有的探测功能都被完整迁移
- 系统调用接口保持不变
- vDSO支持得到保留

### 3. 扩展性考虑

正如提交信息所说，hwprobe功能"只会变得更大"，独立文件为未来扩展提供了更好的基础：
- 新的硬件特性探测可以更容易地添加
- 避免影响其他系统调用的实现
- 便于进行hwprobe特定的优化
