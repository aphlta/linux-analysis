## 代码修改原理分析

### 1. RISC-V hwprobe机制

hwprobe是RISC-V架构特有的系统调用机制，用于向用户空间程序提供硬件能力查询接口。其工作原理：

1. **内核检测**: 内核在启动时通过解析设备树或ACPI表中的ISA字符串来检测CPU支持的扩展
2. **位掩码存储**: 每个扩展用一个位来表示，支持则置1，不支持则为0
3. **用户空间查询**: 用户程序通过riscv_hwprobe系统调用查询特定扩展的支持情况

### 2. Zicond扩展技术背景

Zicond（Integer Conditional operations）扩展提供了条件算术和条件选择/移动操作，主要特点：

1. **标准化**: 基于XVentanaCondOps扩展标准化而来
2. **条件操作**: 提供条件算术运算指令
3. **性能优化**: 减少分支预测失败，提高代码执行效率
4. **QEMU支持**: QEMU已经支持Zicond扩展的模拟

### 3. 实现机制

#### 3.1 扩展检测流程

```
设备树/ACPI ISA字符串 -> 内核解析 -> 设置hwcap位 -> hwprobe查询 -> 用户空间
```

#### 3.2 EXT_KEY宏机制

EXT_KEY宏的作用是将内核的ISA扩展检测结果映射到hwprobe的用户空间接口：

```c
#define EXT_KEY(ext) \
    if (__riscv_isa_extension_available(NULL, RISCV_ISA_EXT_##ext)) \
        pair->value |= RISCV_HWPROBE_EXT_##ext
```
