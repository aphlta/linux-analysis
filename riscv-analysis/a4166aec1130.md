## 3. 代码修改原理

### 3.1 重复代码识别

这个patch解决的核心问题是代码重复（Code Duplication）。在RISC-V的SMP初始化过程中，无论是使用ACPI还是Device Tree来发现CPU，都需要执行相同的操作：

1. **设置CPU 0的操作接口**：`cpu_set_ops(0)`
2. **遍历所有CPU并设置操作接口**：为每个有效的CPU调用`cpu_set_ops(cpuid)`
3. **标记CPU为可用**：调用`set_cpu_possible(cpuid, true)`

### 3.2 重构原理

采用了经典的"提取公共代码"重构技术：

1. **识别公共逻辑**：找出两个函数中相同的代码片段
2. **提取到上层**：将公共代码移动到调用者函数中
3. **保持功能不变**：确保重构后的行为与原来完全一致

### 3.3 cpu_set_ops函数的作用

`cpu_set_ops()` 函数负责为指定的CPU设置操作接口：

```c
void __init cpu_set_ops(void)
{
#if IS_ENABLED(CONFIG_RISCV_SBI)
    if (sbi_probe_extension(SBI_EXT_HSM)) {
        pr_info("SBI HSM extension detected\n");
        cpu_ops = &cpu_ops_sbi;
    }
#endif
}
```

这个函数会：
- 检测SBI HSM（Hart State Management）扩展是否可用
- 如果可用，设置CPU操作接口为SBI版本
- 否则使用默认的spinwait操作接口

### 3.4 执行流程优化

**修改前的执行流程**：
```
setup_smp()
├── if (acpi_disabled)
│   └── of_parse_and_init_cpus()
│       ├── cpu_set_ops(0)
│       ├── 解析Device Tree
│       └── for循环设置其他CPU
└── else
    └── acpi_parse_and_init_cpus()
        ├── cpu_set_ops(0)
        ├── 解析ACPI表
        └── for循环设置其他CPU
```

**修改后的执行流程**：
```
setup_smp()
├── cpu_set_ops(0)                    // 统一执行
├── if (acpi_disabled)
│   └── of_parse_and_init_cpus()      // 只负责解析
└── else
│   └── acpi_parse_and_init_cpus()    // 只负责解析
└── for循环设置其他CPU                 // 统一执行
```

## 6. 技术细节

### 6.1 RISC-V SMP架构

RISC-V架构中，每个CPU核心被称为"hart"（hardware thread）：
- `cpuid_to_hartid_map()`: 维护CPU ID到Hart ID的映射
- `INVALID_HARTID`: 表示无效的Hart ID
- `set_cpu_possible()`: 标记CPU为系统可用

### 6.2 初始化时序

1. **Boot CPU初始化**：CPU 0首先启动并执行初始化
2. **CPU发现**：通过ACPI或Device Tree发现其他CPU
3. **CPU操作设置**：为每个CPU设置适当的操作接口
4. **CPU标记**：将发现的CPU标记为可能启动的CPU

### 6.3 错误处理

代码中包含了适当的错误处理：
- 检查Hart ID的有效性
- 验证CPU ID的范围
- 处理CPU数量超过配置限制的情况
