#### 3.3 SBI扩展处理函数
```c
static int kvm_sbi_ext_sta_handler(struct kvm_vcpu *vcpu, struct kvm_run *run,
                                  struct kvm_vcpu_sbi_return *retdata)
{
       struct kvm_cpu_context *cp = &vcpu->arch.guest_context;
       unsigned long funcid = cp->a6;
       int ret;

       switch (funcid) {
       case SBI_EXT_STA_STEAL_TIME_SET_SHMEM:
               ret = kvm_sbi_sta_steal_time_set_shmem(vcpu);
               break;
       default:
               ret = SBI_ERR_NOT_SUPPORTED;
               break;
       }

       retdata->err_val = ret;

       return 0;
}
```

**分析**:
- 这是SBI STA扩展的主要处理函数
- 从guest上下文的a6寄存器获取功能ID
- 使用switch语句分发不同的SBI功能调用
- 当前只支持`SBI_EXT_STA_STEAL_TIME_SET_SHMEM`功能
- 其他功能返回`SBI_ERR_NOT_SUPPORTED`
- 将结果存储在`retdata->err_val`中返回给guest

## 代码修改原理分析

### 1. SBI STA扩展背景

**SBI STA (Steal Time Accounting)** 是RISC-V SBI规范中的扩展，用于虚拟化环境中的时间窃取统计。

**核心概念**:
- **Steal Time**: 虚拟CPU被hypervisor抢占而无法运行的时间
- **共享内存**: Guest和Host之间共享的内存区域，用于传递steal time信息
- **时间统计**: 帮助Guest OS了解实际可用的CPU时间

### 2. SBI扩展架构

**RISC-V SBI扩展机制**:
- 每个扩展有唯一的扩展ID (Extension ID)
- 扩展内部可以有多个功能ID (Function ID)
- 通过ecall指令进行调用
- 标准化的参数传递和返回值机制

**SBI STA扩展规范**:
- 扩展ID: `SBI_EXT_STA` (0x535441, ASCII "STA")
- 功能ID: `SBI_EXT_STA_STEAL_TIME_SET_SHMEM` (0)
- 用于设置steal time统计的共享内存区域

### 3. KVM SBI扩展框架

**扩展注册机制**:
1. 定义扩展结构 (`kvm_vcpu_sbi_extension`)
2. 实现处理函数和探测函数
3. 在扩展表中注册
4. KVM根据扩展ID分发调用

**处理流程**:
1. Guest发起SBI调用
2. KVM捕获ecall异常
3. 根据扩展ID查找处理函数
4. 调用相应的处理函数
5. 返回结果给Guest

### 4. 骨架实现的设计思路

**分阶段实现**:
- 第一阶段: 创建基础框架和接口
- 第二阶段: 添加数据结构和状态管理
- 第三阶段: 实现完整功能
- 第四阶段: 添加测试和优化

**占位符模式**:
- 函数框架已就位，但返回错误或空值
- 确保编译通过和基本结构正确
- 为后续实现提供清晰的接口
