## 核心功能变更

### 1. 行为反转机制

**原始行为**：
- 输入：CPU集合 + 硬件特性键值对（空值）
- 输出：填充这些CPU集合支持的硬件特性值

**新增行为（RISCV_HWPROBE_WHICH_CPUS标志）**：
- 输入：CPU集合 + 硬件特性键值对（预设值）
- 输出：返回支持这些特定硬件特性值的CPU集合

### 2. 新增的UAPI定义

在`arch/riscv/include/uapi/asm/hwprobe.h`中新增：

```c
/* Flags */
#define RISCV_HWPROBE_WHICH_CPUS       (1 << 0)
```

### 3. 核心比较函数

在`arch/riscv/include/asm/hwprobe.h`中新增了两个关键函数：

#### hwprobe_key_is_bitmask()

```c
static inline bool hwprobe_key_is_bitmask(__s64 key)
{
    switch (key) {
    case RISCV_HWPROBE_KEY_BASE_BEHAVIOR:
    case RISCV_HWPROBE_KEY_IMA_EXT_0:
    case RISCV_HWPROBE_KEY_CPUPERF_0:
        return true;
    }
    return false;
}
```

**功能**：判断硬件特性键是否为位掩码类型。

#### riscv_hwprobe_pair_cmp()

```c
static inline bool riscv_hwprobe_pair_cmp(struct riscv_hwprobe *pair,
                                         struct riscv_hwprobe *other_pair)
{
    if (pair->key != other_pair->key)
        return false;

    if (hwprobe_key_is_bitmask(pair->key))
        return (pair->value & other_pair->value) == other_pair->value;

    return pair->value == other_pair->value;
}
```

**功能**：比较两个硬件特性对，支持两种比较模式：
- **位掩码模式**：检查`other_pair`的所有位是否都在`pair`中设置
- **精确匹配模式**：检查两个值是否完全相等

## 内核实现原理

### 1. 系统调用重构

原来的`do_riscv_hwprobe()`函数被重构为两个专门的函数：

#### hwprobe_get_values() - 原始行为

保持原有的功能：根据CPU集合获取硬件特性值。

#### hwprobe_get_cpus() - 新增行为

```c
static int hwprobe_get_cpus(struct riscv_hwprobe __user *pairs,
                           size_t pair_count, size_t cpusetsize,
                           unsigned long __user *cpus_user,
                           unsigned int flags)
```

**核心算法**：
1. 复制用户空间的CPU集合到内核空间
2. 对每个硬件特性键值对：
   - 验证键的有效性
   - 遍历CPU集合中的每个CPU
   - 获取该CPU的硬件特性值
   - 使用`riscv_hwprobe_pair_cmp()`比较
   - 如果不匹配，从CPU集合中移除该CPU
3. 将过滤后的CPU集合复制回用户空间

### 2. 调度逻辑

新的`do_riscv_hwprobe()`函数根据标志位选择执行路径：

```c
static int do_riscv_hwprobe(struct riscv_hwprobe __user *pairs,
                           size_t pair_count, size_t cpusetsize,
                           unsigned long __user *cpus_user,
                           unsigned int flags)
{
    if (flags & RISCV_HWPROBE_WHICH_CPUS)
        return hwprobe_get_cpus(pairs, pair_count, cpusetsize,
                               cpus_user, flags);

    return hwprobe_get_values(pairs, pair_count, cpusetsize,
                             cpus_user, flags);
}
```

## VDSO支持实现

### 1. 用户空间优化

VDSO（Virtual Dynamic Shared Object）实现允许某些系统调用在用户空间执行，避免内核态切换的开销。

### 2. riscv_vdso_get_cpus()函数

```c
static int riscv_vdso_get_cpus(struct riscv_hwprobe *pairs, size_t pair_count,
                              size_t cpusetsize, unsigned long *cpus,
                              unsigned int flags)
```

**优化策略**：
- 检查CPU集合是否为空
- 验证标志位是否为`RISCV_HWPROBE_WHICH_CPUS`
- 检查系统是否为同构CPU（`avd->homogeneous_cpus`）
- 如果条件不满足，回退到内核系统调用
- 否则使用预缓存的硬件特性值进行快速比较

### 3. VDSO入口函数重构

```c
int __vdso_riscv_hwprobe(struct riscv_hwprobe *pairs, size_t pair_count,
                        size_t cpusetsize, unsigned long *cpus,
                        unsigned int flags)
{
    if (flags & RISCV_HWPROBE_WHICH_CPUS)
        return riscv_vdso_get_cpus(pairs, pair_count, cpusetsize,
                                  cpus, flags);

    return riscv_vdso_get_values(pairs, pair_count, cpusetsize,
                                cpus, flags);
}
```

## 技术原理深度分析

### 1. 位掩码vs精确匹配的设计考虑

**位掩码类型**（如扩展指令集）：
- 使用`(pair->value & other_pair->value) == other_pair->value`
- 允许CPU支持超集的特性，只要包含所需的特性即可
- 例如：CPU支持特性A+B+C，查询特性A+B时返回匹配

**精确匹配类型**（如架构版本）：
- 使用`pair->value == other_pair->value`
- 要求完全相等
- 例如：CPU架构版本必须精确匹配

### 2. 性能优化策略

**内核态优化**：
- 使用`cpumask`数据结构高效管理CPU集合
- 单CPU掩码重用（`one_cpu`）避免重复分配
- 提前退出机制（`clear_all`标志）

**用户态优化**：
- VDSO避免系统调用开销
- 同构CPU系统的快速路径
- 预缓存硬件特性值（`avd->all_cpu_hwprobe_values`）

### 3. 错误处理机制

- 无效键处理：设置`key = -1`并清空CPU集合
- 用户空间内存访问错误：返回`-EFAULT`
- 参数验证：检查`cpusetsize`和`cpus`指针

## 应用场景分析

### 1. 性能敏感应用

应用程序可以查询支持特定向量扩展的CPU集合，然后将计算密集型任务调度到这些CPU上。

```c
struct riscv_hwprobe probe = {
    .key = RISCV_HWPROBE_KEY_IMA_EXT_0,
    .value = RISCV_HWPROBE_EXT_ZVE32X  // 查询支持向量扩展的CPU
};
cpu_set_t cpus;
// 设置初始CPU集合
riscv_hwprobe(&probe, 1, sizeof(cpus), &cpus, RISCV_HWPROBE_WHICH_CPUS);
// cpus现在包含支持向量扩展的CPU
```

### 2. 异构系统支持

在big.LITTLE类型的异构RISC-V系统中，不同CPU核心可能支持不同的扩展指令集。

### 3. 运行时优化

动态库可以在运行时检测可用的CPU特性，选择最优的代码路径。
