## 修改内容详细分析

### 1. 新增配置选项

在 `arch/riscv/Kconfig.errata` 中新增了 `ERRATA_STARFIVE_JH7100` 配置选项：

```kconfig
config ERRATA_STARFIVE_JH7100
       bool "StarFive JH7100 support"
       depends on ARCH_STARFIVE && NONPORTABLE
       select DMA_GLOBAL_POOL
       select RISCV_DMA_NONCOHERENT
       select RISCV_NONSTANDARD_CACHE_OPS
       select SIFIVE_CCACHE
       default n
       help
         The StarFive JH7100 was a test chip for the JH7110 and has
         caches that are non-coherent with respect to peripheral DMAs.
         It was designed before the Zicbom extension so needs non-standard
         cache operations through the SiFive cache controller.

         Say "Y" if you want to support the BeagleV Starlight and/or
         StarFive VisionFive V1 boards.
```

**关键特性：**
- 依赖于 `ARCH_STARFIVE` 和 `NONPORTABLE` 配置
- 自动选择多个DMA和缓存相关的配置选项
- 默认关闭，需要用户明确启用
- 支持BeagleV Starlight和StarFive VisionFive V1开发板

## 技术原理分析

### 1. StarFive JH7100芯片特性

**芯片背景：**
- JH7100是StarFive公司为JH7110设计的测试芯片
- 设计时间早于RISC-V Zicbom扩展标准化
- 缓存系统与外设DMA不一致（non-coherent）
- 需要通过SiFive缓存控制器进行非标准缓存操作

**硬件限制：**
- 缺乏标准的Zicbom缓存管理扩展支持
- DMA操作与CPU缓存之间存在一致性问题
- 需要软件显式管理缓存一致性

### 2. 配置选项技术分析

#### DMA_GLOBAL_POOL
- **作用:** 启用全局DMA内存池
- **原理:** 为DMA操作分配专用的内存区域，避免缓存一致性问题
- **必要性:** JH7100的DMA与缓存不一致，需要专门的内存管理

#### RISCV_DMA_NONCOHERENT
- **作用:** 启用RISC-V非一致性DMA支持
- **功能:** 提供DMA操作前后的缓存同步机制
- **实现:** 选择以下架构特性：
  - `ARCH_HAS_DMA_PREP_COHERENT`
  - `ARCH_HAS_SETUP_DMA_OPS`
  - `ARCH_HAS_SYNC_DMA_FOR_CPU`
  - `ARCH_HAS_SYNC_DMA_FOR_DEVICE`
  - `DMA_BOUNCE_UNALIGNED_KMALLOC`（如果启用SWIOTLB）

#### RISCV_NONSTANDARD_CACHE_OPS
- **作用:** 启用非标准缓存操作支持
- **实现:** 通过函数指针支持非标准的非一致性系统缓存管理
- **用途:** 处理JH7100特有的缓存管理需求

#### SIFIVE_CCACHE
- **作用:** 启用SiFive缓存控制器支持
- **功能:** 提供通过SiFive缓存控制器进行缓存操作的接口
- **重要性:** JH7100依赖SiFive缓存控制器进行缓存管理

### 3. DMA一致性问题解决方案

#### 问题描述
```
CPU缓存 <--不一致--> 外设DMA
    ↓                    ↓
  主内存 <-----------> 设备内存
```

#### 解决方案
```
CPU操作 -> 缓存同步 -> DMA操作 -> 缓存失效 -> CPU读取
    ↓         ↓          ↓          ↓         ↓
  写缓存   刷新缓存   DMA传输   失效缓存   读内存
```

**具体流程：**
1. **DMA写入前:** 刷新CPU缓存到内存
2. **DMA操作:** 设备直接访问内存
3. **DMA完成后:** 失效相关CPU缓存行
4. **CPU访问:** 从内存重新加载数据

### 4. 缓存操作实现机制

#### 标准Zicbom vs 非标准操作

**标准Zicbom操作：**
```c
// 标准缓存块操作指令
cbo.clean   // 清理缓存块
cbo.flush   // 刷新缓存块
cbo.inval   // 失效缓存块
```

**JH7100非标准操作：**
```c
// 通过SiFive缓存控制器
sifive_ccache_flush_range(start, size);
sifive_ccache_clean_range(start, size);
sifive_ccache_inval_range(start, size);
```

- 只在必要时进行缓存同步
- 批量处理缓存操作以减少开销
- 利用硬件特性优化同步过程

### 3. 维护复杂性

**代码维护：**

- 需要与硬件特性保持同步
- 测试覆盖面的扩展需求
