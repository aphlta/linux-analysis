## 修改概述

这个patch主要修改了RISC-V KVM selftests中SBI扩展寄存器的处理方式，将SBI扩展寄存器从基础寄存器集合中移除，并像ISA扩展寄存器一样进行过滤处理。

## 修改原理分析

### 问题背景

1. **平台兼容性问题**: SBI扩展寄存器在不同平台上的可用性不同
2. **PMU扩展依赖**: PMU SBI扩展依赖于sscofpmf硬件特性，在没有该特性的平台上不可用
3. **DBCN扩展版本依赖**: DBCN扩展只在较新的内核版本中存在
4. **测试稳定性**: 将这些寄存器放在基础寄存器集合中会导致测试在某些平台上失败

### 解决方案

1. **分离策略**: 将SBI扩展寄存器从基础寄存器集合中分离出来
2. **过滤机制**: 像ISA扩展寄存器一样，对SBI扩展寄存器进行过滤处理
3. **独立配置**: 为不同的SBI扩展创建独立的测试配置
4. **特性检测**: 在测试前检测特性是否可用，不可用则跳过测试

### 技术实现

1. **类型系统**: 通过`feature_type`字段区分ISA扩展和SBI扩展
2. **统一接口**: 使用相同的宏模式处理不同类型的扩展
3. **动态检测**: 在运行时检测扩展是否可用
4. **模块化设计**: 每个扩展都有独立的配置和寄存器列表

## 总结

这个patch通过重构SBI扩展寄存器的处理方式，解决了RISC-V KVM selftests在不同平台上的兼容性问题。主要改进包括：

1. 将SBI扩展寄存器从基础寄存器集合中分离
2. 实现了与ISA扩展寄存器相同的过滤和检测机制
3. 为PMU和DBCN等可能不可用的扩展创建了独立的测试配置
4. 提供了统一的宏接口来处理不同类型的扩展

这些改进显著提高了测试的稳定性和可维护性，同时为未来的扩展提供了良好的框架基础。
