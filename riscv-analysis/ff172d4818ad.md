## 3. 技术原理分析

### 3.1 vmemmap机制概述

vmemmap是Linux内核中用于管理struct page数组的虚拟内存映射机制。它提供了一个虚拟连续的地址空间来存储所有物理页面的struct page结构体。

**核心概念:**
- **vmemmap区域:** 专门用于存储struct page数组的虚拟地址空间
- **线性映射:** 每个物理页面对应一个固定位置的struct page结构体
- **PFN到struct page的转换:** `pfn_to_page(pfn) = vmemmap + pfn`

### 3.2 传统basepage映射 vs hugepage映射

#### 传统basepage映射
- 使用4KB页面映射vmemmap区域
- 每个4KB页面需要一个PTE表项
- TLB条目较多，TLB压力大

#### hugepage映射
- 使用2MB大页面映射vmemmap区域
- 每个2MB页面只需要一个PMD表项
- 显著减少TLB条目数量，提高TLB利用率

### 3.3 关键函数分析

#### vmemmap_set_pmd()
```c
void __meminit vmemmap_set_pmd(pmd_t *pmd, void *p, int node,
                              unsigned long addr, unsigned long next)
{
       pmd_set_huge(pmd, virt_to_phys(p), PAGE_KERNEL);
}
```

**功能:** 设置PMD表项为hugepage映射
- `pmd_set_huge()`: 设置PMD表项指向一个2MB大页面
- `virt_to_phys(p)`: 将虚拟地址转换为物理地址
- `PAGE_KERNEL`: 设置内核页面权限

#### vmemmap_check_pmd()
```c
int __meminit vmemmap_check_pmd(pmd_t *pmdp, int node,
                               unsigned long addr, unsigned long next)
{
       vmemmap_verify((pte_t *)pmdp, node, addr, next);
       return 1;
}
```

**功能:** 验证PMD映射的正确性
- 调用`vmemmap_verify()`验证映射
- 返回1表示使用hugepage映射

#### vmemmap_populate_hugepages()
这是通用内存管理子系统提供的函数，用于使用hugepage填充vmemmap区域：

1. **遍历地址范围:** 按PMD边界遍历vmemmap区域
2. **分配大页面:** 调用`vmemmap_alloc_block_buf(PMD_SIZE, node, altmap)`分配2MB内存块
3. **设置PMD映射:** 调用架构特定的`vmemmap_set_pmd()`设置PMD表项
4. **回退机制:** 如果大页面分配失败，回退到basepage映射

### 3.4 RISC-V特定考虑

#### 页表级别限制
注释中提到的重要限制：
```
* can't use hugepage mappings for 2-level page table because in case of
* memory hotplug, we are not able to update all the page tables with
* the new PMDs.
```

**原因分析:**
- RISC-V支持2级、3级、4级页表
- 在2级页表中，PMD直接映射到PGD
- 内存热插拔时，更新所有页表的PMD项会很复杂
- 因此只在3级以上页表中使用hugepage映射

## 4. 性能影响分析

### 4.1 TLB优化效果

#### 修改前（basepage映射）
```
---[ vmemmap start ]---
0xffff8d8002000000-0xffff8d8012000000    0x000000046ec00000       256M PTE .   ..     ..   D A G . . W R V
---[ vmemmap end ]---
```

#### 修改后（hugepage映射）
```
---[ vmemmap start ]---
0xffff8d8002000000-0xffff8d8012000000    0x000000046ec00000       256M PMD .   ..     ..   D A G . . W R V
---[ vmemmap end ]---
```

#### 性能提升分析

**TLB条目减少:**
- 修改前：256MB ÷ 4KB = 65,536个TLB条目
- 修改后：256MB ÷ 2MB = 128个TLB条目
- **TLB条目减少了99.8%**

**内存访问性能:**
- **TLB命中率提升:** 更少的TLB条目意味着更高的命中率
- **TLB miss减少:** 显著减少TLB miss导致的页表遍历
- **缓存友好性:** 大页面减少了页表缓存压力

### 4.2 内存开销分析

**页表开销减少:**
- 修改前：需要65,536个PTE表项（每个8字节）= 512KB页表开销
- 修改后：只需要128个PMD表项（每个8字节）= 1KB页表开销
- **页表内存开销减少99.8%**

**内存碎片化:**
- hugepage映射减少了内存碎片化
- 提高了内存分配效率
