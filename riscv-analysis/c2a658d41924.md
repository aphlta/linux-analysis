## 修改概述

这个patch为RISC-V架构实现了基于Vector扩展的用户空间内存拷贝优化，主要针对`copy_to_user()`和`copy_from_user()`函数。当Vector扩展可用且拷贝数据量足够大时，使用Vector指令进行高效的内存拷贝操作。

## 详细修改分析

### 1. Kconfig配置新增

在`arch/riscv/Kconfig`中新增了配置选项：

```kconfig
config RISCV_ISA_V_UCOPY_THRESHOLD
    int "Threshold size for vectorized user copies"
    depends on RISCV_ISA_V
    default 768
    help
      Prefer using vectorized copy_to_user()/copy_from_user() when the
      workload size exceeds this value.
```

**作用：**
- 定义了使用Vector拷贝的阈值大小，默认为768字节
- 只有当拷贝数据量超过此阈值时才使用Vector指令
- 可在编译时配置，提供了灵活性

### 2. 新增Vector用户空间拷贝汇编实现

新文件`arch/riscv/lib/uaccess_vector.S`实现了核心的Vector拷贝逻辑：

**关键特性：**
- 使用`vsetvli`指令动态设置Vector长度
- 采用`e8, m8`配置（8位元素，LMUL=8）最大化吞吐量
- 实现了完善的异常处理机制
- 支持用户空间访问权限控制（SR_SUM位）

**核心循环逻辑：**
```assembly
loop:
    vsetvli iVL, iNum, e8, ELEM_LMUL_SETTING, ta, ma
    fixup vle8.v vData, (pSrc), 10f
    sub iNum, iNum, iVL
    add pSrc, pSrc, iVL
    fixup vse8.v vData, (pDst), 11f
    add pDst, pDst, iVL
    bnez iNum, loop
```

**异常处理机制：**
- 标签`10f`：处理Vector加载异常，与正常退出共享
- 标签`11f`：处理Vector存储异常，需要特殊处理VSTART寄存器
- 使用`_asm_extable`宏建立异常表项

### 3. C语言包装函数

新文件`arch/riscv/lib/riscv_v_helpers.c`提供了C语言接口：

**核心函数`enter_vector_usercopy()`：**
- 检查SIMD上下文可用性（`may_use_simd()`）
- 管理Vector上下文（`kernel_vector_begin()/end()`）
- 实现Vector拷贝失败时的标量回退机制
- 处理部分拷贝完成的情况

**回退机制：**
当Vector拷贝遇到页面错误或其他异常时，会计算已拷贝的字节数，调整源和目标指针，然后回退到标量拷贝完成剩余工作。

### 4. 原有uaccess.S的修改

在`arch/riscv/lib/uaccess.S`中添加了Vector拷贝的入口逻辑：

```assembly
#ifdef CONFIG_RISCV_ISA_V
ALTERNATIVE("j fallback_scalar_usercopy", "nop", 0, RISCV_ISA_EXT_v, CONFIG_RISCV_ISA_V)
REG_L   t0, riscv_v_usercopy_threshold
bltu    a2, t0, fallback_scalar_usercopy
tail enter_vector_usercopy
#endif
```

**实现机制：**
- 使用`ALTERNATIVE`宏实现运行时特性检测
- 如果Vector扩展不可用，直接跳转到标量实现
- 比较拷贝大小与阈值，小于阈值使用标量拷贝
- 大于阈值时调用Vector拷贝函数

### 5. 构建系统修改

`arch/riscv/lib/Makefile`的修改：
- 将`uaccess_vector.o`和`riscv_v_helpers.o`加入Vector扩展的编译目标
- 确保只在启用Vector扩展时编译相关代码

## 技术原理分析

### 1. Vector扩展优势

**并行处理能力：**
- RISC-V Vector扩展支持可变长度的SIMD操作
- 使用LMUL=8配置可以最大化单次操作的数据量
- 理论上可以达到8倍于标量操作的吞吐量

**自适应长度：**
- `vsetvli`指令可以根据剩余数据量自动调整Vector长度
- 避免了固定长度SIMD的边界处理复杂性

### 2. 异常处理设计

**用户空间访问风险：**
- 用户空间页面可能不在内存中，访问时会触发页面错误
- Vector操作中的异常需要精确定位到具体的元素

**VSTART寄存器的作用：**
- 记录Vector指令执行过程中发生异常的元素索引
- 在存储异常处理中，需要根据VSTART调整剩余字节数
- 确保回退到标量拷贝时不会重复处理已完成的元素

### 3. 性能优化策略

**阈值设计：**
- 默认768字节的阈值是基于经验的启发式值
- 考虑了Vector上下文切换的开销
- 小数据量使用标量拷贝避免不必要的开销

**上下文管理：**
- 使用`kernel_vector_begin()/end()`管理Vector状态
- 确保Vector寄存器状态的正确保存和恢复
- 避免与用户空间Vector使用的冲突
