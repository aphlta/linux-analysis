## 2. 修改内容详细分析

### 2.1 核心修改

本patch在RISC-V架构的Kconfig文件中添加了一行配置：

```diff
+       select FTRACE_MCOUNT_USE_PATCHABLE_FUNCTION_ENTRY if DYNAMIC_FTRACE
```

这个修改位于 `arch/riscv/Kconfig` 文件的第71行，在RISC-V架构的配置选项中。

### 2.2 修改背景

该patch是对之前commit afc76b8b8011 ("riscv: Using PATCHABLE_FUNCTION_ENTRY instead of MCOUNT") 的补充。在afc76b8b8011中，RISC-V架构已经添加了对 `-fpatchable-function-entry` 的支持，但缺少了告知构建系统不要运行recordmcount工具的配置。

## 3. 技术原理分析

### 3.1 FTRACE机制演进

#### 传统mcount机制
在传统的ftrace实现中，使用mcount机制：
- 编译器在每个函数入口插入对mcount的调用
- 需要recordmcount工具扫描目标文件，找到所有mcount调用点
- 构建__mcount_loc段，记录所有mcount调用的位置

#### PATCHABLE_FUNCTION_ENTRY机制
新的机制使用 `-fpatchable-function-entry` 编译选项：
- 编译器在函数入口前插入指定数量的NOP指令
- 不需要recordmcount工具处理
- 运行时可以直接patch这些NOP指令为跳转指令

### 3.2 RISC-V的实现细节

在afc76b8b8011 commit中，RISC-V架构的变化：

**编译选项变化**：
```makefile
# 在arch/riscv/Makefile中添加
ifeq ($(CONFIG_DYNAMIC_FTRACE),y)
       LDFLAGS_vmlinux := --no-relax
+      KBUILD_CPPFLAGS += -DCC_USING_PATCHABLE_FUNCTION_ENTRY
+      CC_FLAGS_FTRACE := -fpatchable-function-entry=8
endif
```

**函数调用模式变化**：

传统mcount方式：
```assembly
<funca>:
        addi sp,sp,-16
        sd   ra,8(sp)
        sd   s0,0(sp)
        addi s0,sp,16
        mv   a5,ra
        mv   a0,a5
        auipc ra,0x0 -> nop
        jalr  -296(ra) <_mcount@plt> ->nop
        ...
```

新的patchable-function-entry方式：
```assembly
<funca>:
        nop -> REG_S ra, -SZREG(sp)
        nop -> auipc ra, 0x?
        nop -> jalr ?(ra)
        nop -> REG_L ra, -SZREG(sp)
        ...
```

### 3.3 FTRACE_MCOUNT_USE_PATCHABLE_FUNCTION_ENTRY的作用

这个配置选项的主要作用是：

1. **禁用recordmcount工具**：告知构建系统不需要运行recordmcount工具来扫描mcount调用点
2. **优化构建过程**：避免不必要的目标文件处理步骤
3. **确保一致性**：确保构建系统知道当前架构使用的是patchable-function-entry机制

在 `scripts/Makefile.build` 中的相关逻辑：
```makefile
ifdef CONFIG_FTRACE_MCOUNT_USE_RECORDMCOUNT
# compiler will not generate __mcount_loc use recordmcount or recordmcount.pl
# ... recordmcount相关处理逻辑
endif
```

当设置了 `FTRACE_MCOUNT_USE_PATCHABLE_FUNCTION_ENTRY` 时，`CONFIG_FTRACE_MCOUNT_USE_RECORDMCOUNT` 不会被设置，从而跳过recordmcount处理。
