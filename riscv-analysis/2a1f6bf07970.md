## 2. Patch 概述

这个patch为RISC-V KVM添加了一个新的VCPU请求类型`KVM_REQ_STEAL_UPDATE`，用于通知VCPU记录其steal-time信息。该请求在检测到VCPU任务在一段时间内未被分配到物理CPU时触发，通过在vcpu-load时发起请求来实现。

## 4. 技术原理分析

### 4.1 Steal Time概念

**定义**: Steal time是指虚拟CPU被hypervisor调度出去，无法执行指令的时间。

**重要性**:
- 帮助虚拟机内核更准确地进行时间统计
- 改善虚拟机内调度器的决策
- 提供虚拟化开销的可见性

### 4.2 KVM请求机制

KVM使用请求机制来处理需要在VCPU上下文中执行的异步操作：

1. **请求发起**: 通过`kvm_make_request()`设置请求位
2. **请求检查**: 在VCPU运行循环中通过`kvm_check_request()`检查
3. **请求处理**: 调用相应的处理函数

### 4.3 VCPU加载时机

`kvm_arch_vcpu_load()`在以下情况被调用：
- VCPU从一个物理CPU迁移到另一个
- VCPU被重新调度到物理CPU
- 这是检测steal time的理想时机

### 4.4 SBI STA扩展架构

基于代码分析，RISC-V KVM的steal-time支持基于SBI STA (Steal-Time Accounting)扩展：

```c
// VCPU架构结构中的STA字段
struct {
    gpa_t shmem;      // 共享内存地址
    u64 last_steal;   // 上次记录的steal time
} sta;
```
