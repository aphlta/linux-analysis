## Commit 信息

- **作者**: Charlie Jenkins <charlie@rivosinc.com>
- **日期**: 2024年1月4日
- **标题**: riscv: Fix relocation_hashtable size

## 问题描述

这个patch修复了RISC-V架构中模块加载时relocation_hashtable大小计算错误的问题。在原始代码中，`kmalloc_array`函数调用时使用了错误的元素大小参数，导致分配的内存不足。

## 代码修改详情

### 修改位置
文件：`arch/riscv/kernel/module.c`
函数：`initialize_relocation_hashtable`

### 具体修改
```c
// 修改前
*relocation_hashtable = kmalloc_array(hashtable_size,
                                     sizeof(*relocation_hashtable),
                                     GFP_KERNEL);

// 修改后  
*relocation_hashtable = kmalloc_array(hashtable_size,
                                     sizeof(**relocation_hashtable),
                                     GFP_KERNEL);
```

## 技术原理分析

### 1. 数据结构背景

在RISC-V模块加载过程中，`relocation_hashtable`是一个指向`struct hlist_head`数组的指针：

```c
struct hlist_head *relocation_hashtable;
```

其中`struct hlist_head`是Linux内核中的哈希链表头结构，定义在`include/linux/list.h`中：

```c
struct hlist_head {
    struct hlist_node *first;
};
```

### 2. 问题根源

在原始代码中：
- `relocation_hashtable`是`struct hlist_head **`类型（指向指针的指针）
- `*relocation_hashtable`是`struct hlist_head *`类型（指向数组的指针）
- `sizeof(*relocation_hashtable)`计算的是指针的大小（在64位系统上是8字节）
- `sizeof(**relocation_hashtable)`计算的是`struct hlist_head`结构体的大小

### 3. 内存分配错误

使用`sizeof(*relocation_hashtable)`会导致：
- 在64位系统上，每个元素只分配8字节（指针大小）
- 而实际需要的是`sizeof(struct hlist_head)`字节
- 由于`struct hlist_head`只包含一个指针成员，在64位系统上也是8字节，所以这个bug在某些情况下可能不会立即显现

### 4. 潜在风险

虽然在当前的`struct hlist_head`定义下，两种计算方式的结果相同，但：
1. 代码语义不正确，违反了类型安全原则
2. 如果将来`struct hlist_head`结构发生变化，会导致严重的内存错误
3. 静态分析工具（如Coccinelle）会检测到这种类型不匹配问题
