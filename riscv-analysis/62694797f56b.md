## 修改概述

这个patch对RISC-V架构的5个汇编文件进行了头文件包含的优化，将`#include <asm-generic/export.h>`替换为`#include <linux/export.h>`。这是一个代码清理和标准化的改进。

## 修改的文件列表

1. `arch/riscv/kernel/mcount-dyn.S` - 动态函数跟踪相关
2. `arch/riscv/kernel/mcount.S` - 函数跟踪相关
3. `arch/riscv/lib/clear_page.S` - 页面清零优化函数
4. `arch/riscv/lib/tishift.S` - 128位整数移位操作
5. `arch/riscv/lib/uaccess.S` - 用户空间访问函数

每个文件的修改都是相同的模式：
```diff
-#include <asm-generic/export.h>
+#include <linux/export.h>
```

## 技术原理分析

### 1. 头文件层次结构

- **asm-generic/export.h**: 这是一个通用的架构无关的包装器文件
- **linux/export.h**: 这是内核符号导出的核心头文件

### 2. 修改原因

根据commit message，`asm-generic/export.h`实际上是`linux/export.h`的一个包装器，并且明确建议直接使用`linux/export.h`。这种修改有以下好处：

1. **减少间接包含**: 直接包含核心头文件，避免不必要的包装层
2. **提高编译效率**: 减少预处理器需要处理的文件数量
3. **代码标准化**: 遵循内核开发的最佳实践
4. **维护简化**: 减少头文件依赖链的复杂性

### 3. 符号导出机制

这些文件都使用了内核的符号导出机制，通过`EXPORT_SYMBOL`宏将汇编函数导出给其他内核模块使用。`linux/export.h`提供了以下关键功能：

- 定义了`EXPORT_SYMBOL`、`EXPORT_SYMBOL_GPL`等宏
- 处理模块版本控制（CONFIG_MODVERSIONS）
- 支持符号命名空间
- 提供架构相关的符号引用格式

## 影响的功能模块

### 1. 函数跟踪（ftrace）
- `mcount.S`和`mcount-dyn.S`是ftrace功能的核心组件
- 提供函数调用跟踪和性能分析支持
- 导出的符号被内核跟踪子系统使用

### 2. 内存管理优化
- `clear_page.S`提供了高效的页面清零实现
- 可能包含RISC-V特定的优化指令
- 被内存管理子系统广泛使用

### 3. 数学运算支持
- `tishift.S`实现128位整数的移位操作
- 支持编译器生成的长整数运算
- 为用户空间程序提供底层支持

### 4. 用户空间访问
- `uaccess.S`提供安全的用户空间内存访问
- 包含异常处理机制
- 是系统调用实现的基础组件
