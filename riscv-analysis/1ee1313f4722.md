## 3. 涉及的Linux内核机制

### 3.1 ELF重定位机制

#### 3.1.1 重定位的基本概念

重定位是链接器和加载器的核心功能，用于解决编译时无法确定的地址引用问题：

- **编译时地址未知**: 模块编译时不知道加载地址
- **符号引用**: 模块可能引用其他模块或内核符号
- **位置无关代码**: 支持代码在不同地址运行

#### 3.1.2 ELF重定位表结构

```c
// ELF重定位条目结构
typedef struct {
    Elf64_Addr r_offset;    // 需要重定位的位置偏移
    Elf64_Xword r_info;     // 重定位类型和符号索引
    Elf64_Sxword r_addend;  // 重定位加数
} Elf64_Rela;

// 信息提取宏
#define ELF_RISCV_R_SYM(i)  ((i) >> 32)           // 符号表索引
#define ELF_RISCV_R_TYPE(i) ((i) & 0xffffffff)    // 重定位类型
```

#### 3.1.3 RISC-V重定位类型

```c
// 主要的RISC-V重定位类型
enum {
    R_RISCV_NONE = 0,
    R_RISCV_32 = 1,           // 32位绝对地址
    R_RISCV_64 = 2,           // 64位绝对地址
    R_RISCV_CALL_PLT = 19,    // 函数调用（可能需要PLT）
    R_RISCV_GOT_HI20 = 20,    // GOT表引用的高20位
    R_RISCV_PCREL_HI20 = 23,  // PC相对地址的高20位
    R_RISCV_PLT32 = 59,       // 32位PLT相对地址
};
```

#### 3.2.2 重定位处理核心函数

```c
int apply_relocate_add(Elf_Shdr *sechdrs, const char *strtab,
                      unsigned int symindex, unsigned int relsec,
                      struct module *me)
{
    Elf_Rela *rel = (void *) sechdrs[relsec].sh_addr;
    int (*handler)(struct module *me, void *location, Elf_Addr v);
    
    // 遍历所有重定位条目
    for (i = 0; i < num_relocations; i++) {
        // 1. 计算重定位位置
        location = (void *)sechdrs[sechdrs[relsec].sh_info].sh_addr + rel[i].r_offset;
        
        // 2. 获取目标符号值
        v = sym->st_value + rel[i].r_addend;
        
        // 3. 获取重定位类型并调用处理函数
        type = ELF_RISCV_R_TYPE(rel[i].r_info);
        handler = reloc_handlers[type].reloc_handler;
        res = handler(me, location, v);
    }
    
    return 0;
}
```

### 3.3 RISC-V架构特定机制

#### 3.3.1 PLT/GOT结构定义

```c
// GOT条目结构
struct got_entry {
    unsigned long symbol_addr;  // 实际变量地址
};

// PLT条目结构 - 包含三条RISC-V指令
struct plt_entry {
    u32 insn_auipc;  // auipc t0, 0x0
    u32 insn_ld;     // ld    t1, 0x10(t0)
    u32 insn_jr;     // jr    t1
};

// 模块架构特定数据
struct mod_arch_specific {
    struct mod_section got;
    struct mod_section plt;
    struct mod_section got_plt;
};
```

#### 3.3.2 PLT跳转指令序列

每个PLT条目由三条RISC-V指令组成：

```assembly
# PLT条目的指令序列
auipc t3, %pcrel_hi(got_plt_entry)  # 加载GOT.PLT地址高20位
ld    t3, %pcrel_lo(got_plt_entry)(t3) # 从GOT.PLT加载目标地址
jalr  zero, t3, 0                    # 跳转到目标地址
```

#### 3.3.3 重定位处理函数

##### R_RISCV_PLT32处理

```c
static int apply_r_riscv_plt32_rela(struct module *me, void *location, Elf_Addr v)
{
    ptrdiff_t offset = (void *)v - location;

    if (!riscv_insn_valid_32bit_offset(offset)) {
        // 超出32位偏移范围，使用PLT跳转
        if (IS_ENABLED(CONFIG_MODULE_SECTIONS)) {
            offset = (void *)module_emit_plt_entry(me, v) - location;
        } else {
            pr_err("%s: target %016llx can not be addressed by the 32-bit offset from PC = %p\n",
                   me->name, (long long)v, location);
            return -EINVAL;
        }
    }

    *(u32 *)location = (u32)offset;  // 直接写入32位偏移值
    return 0;
}
```

##### R_RISCV_CALL_PLT处理

```c
static int apply_r_riscv_call_plt_rela(struct module *me, void *location, Elf_Addr v)
{
    ptrdiff_t offset = (void *)v - location;
    u32 hi20, lo12;

    if (!riscv_insn_valid_32bit_offset(offset)) {
        // 超出32位偏移范围，使用PLT跳转
        offset = (void *)module_emit_plt_entry(me, v) - location;
    }

    // 生成auipc + jalr指令对
    hi20 = (offset + 0x800) & 0xfffff000;
    lo12 = (offset - hi20) & 0xfff;
    riscv_insn_rmw(location, 0xfff, hi20);        // 修改auipc指令
    return riscv_insn_rmw(location + 4, 0xfffff, lo12 << 20);  // 修改jalr指令
}
```

## 4. 关键技术问题分析

### 4.1 问题1: 重定位类型识别机制

**问题描述**: 如何准确识别需要PLT条目的重定位类型？

**技术挑战**:
- 不同重定位类型的PLT需求不同
- 编译器优化可能影响重定位类型选择
- 链接时和加载时的处理差异

**解决方案**:
1. **静态分析**: 在`count_max_entries()`中预分析所有重定位条目
2. **动态创建**: 在实际处理时按需创建PLT条目
3. **重复检测**: 避免为相同目标创建多个PLT条目

### 4.2 问题2: PLT跳转的性能优化

**问题描述**: 如何在保证功能正确性的前提下优化PLT跳转性能？

**性能考虑**:
- 直接跳转 vs PLT跳转的延迟差异
- 指令缓存和数据缓存的影响
- 分支预测器的行为

**优化策略**:
1. **范围检查优先**: 优先使用直接跳转
2. **PLT条目复用**: 相同目标共享PLT条目
3. **内存布局优化**: PLT条目紧凑排列

### 4.3 问题3: 内存管理挑战

**问题描述**: 如何高效管理PLT/GOT表的内存分配？

**技术挑战**:
1. **预分配准确性**: 如何准确估算需要的PLT/GOT条目数量？
2. **内存碎片**: 如何减少PLT/GOT表造成的内存碎片？
3. **动态扩展**: 是否需要支持PLT/GOT表的动态扩展？

**设计权衡**:
- 预分配 vs 动态分配的内存效率
- 空间利用率 vs 分配复杂度
- 模块卸载时的内存回收策略

### 4.4 问题4: 架构扩展兼容性

**问题描述**: RISC-V架构扩展如何影响重定位机制？

**技术挑战**:
