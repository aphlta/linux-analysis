## Patch 概述

这个patch为RISC-V架构添加了标量加密(Scalar Crypto) ISA扩展的解析支持。主要目的是支持RISC-V标量加密规范中定义的"捆绑"扩展，如Zk、Zkn、Zks和Zbk等，这些扩展是其他多个扩展的简写形式。

## 修改的文件

1. **arch/riscv/include/asm/cpufeature.h** - 增加了4行代码
2. **arch/riscv/include/asm/hwcap.h** - 增加了11行代码  
3. **arch/riscv/kernel/cpufeature.c** - 主要修改文件，增加了118行，删除了24行

总计：新增109行，删除24行

## 详细代码修改分析

### 1. 数据结构扩展

在`riscv_isa_ext_data`结构体中新增了两个成员：
- `subset_ext_size`: 子扩展的数量
- `subset_ext_ids`: 子扩展ID数组的指针

这些新成员用于支持"捆绑"扩展，允许一个扩展名代表多个子扩展。

### 2. 新增的标量加密扩展定义

添加了以下RISC-V标量加密扩展的支持：

#### 基础加密扩展
- **Zbkb**: 位操作加密扩展
- **Zbkc**: 进位无关乘法扩展
- **Zbkx**: 交叉乘法扩展

#### AES加密扩展
- **Zknd**: NIST AES解密扩展
- **Zkne**: NIST AES加密扩展
- **Zknh**: NIST AES哈希扩展

#### 其他加密扩展
- **Zkr**: 熵源扩展
- **Zkt**: 数据无关执行扩展

#### 捆绑扩展
- **Zk**: Zkn + Zkr + Zkt的组合
- **Zkn**: Zbkb + Zbkc + Zbkx + Zknd + Zkne + Zknh的组合
- **Zks**: Zbkb + Zbkc + Zbkx + Zksed + Zksh的组合
- **Zbk**: Zbkb + Zbkc + Zbkx的组合

### 3. 解析逻辑改进

#### ISA字符串解析
新增了`match_isa_ext()`函数来处理扩展匹配，支持：
- 单个扩展的直接匹配
- 捆绑扩展的子扩展自动设置

#### 设备树属性解析
在`riscv_fill_hwcap_from_ext_list()`函数中：
- 增加了对捆绑扩展的支持
- 当检测到捆绑扩展时，自动设置所有相关的子扩展
- 保持了向后兼容性

## 技术原理

### 1. 捆绑扩展机制

标量加密规范定义了层次化的扩展结构：
```
Zk (顶层捆绑)
├── Zkn (加密捆绑)
│   ├── Zbkb (位操作)
│   ├── Zbkc (进位无关乘法)
│   ├── Zbkx (交叉乘法)
│   ├── Zknd (AES解密)
│   ├── Zkne (AES加密)
│   └── Zknh (AES哈希)
├── Zkr (熵源)
└── Zkt (数据无关执行)
```

### 2. 解析流程

1. **ISA字符串解析**：
   - 解析设备树中的"riscv,isa"属性
   - 识别扩展名称
   - 如果是捆绑扩展，递归设置所有子扩展

2. **扩展属性解析**：
   - 解析"riscv,isa-extensions"属性中的独立扩展
   - 支持新的捆绑扩展语法

3. **硬件能力设置**：
   - 设置相应的ISA位图
   - 更新hwcap寄存器（仅单字母扩展）

### 3. 向后兼容性

- 保持对现有单个扩展的完全支持
- 新的捆绑机制不影响现有代码
- 设备树可以混合使用单个扩展和捆绑扩展

## 使用示例

### 设备树配置示例
```dts
cpu {
    riscv,isa = "rv64imafdc_zk";
    // 或者
    riscv,isa-extensions = "zk";
};
```
