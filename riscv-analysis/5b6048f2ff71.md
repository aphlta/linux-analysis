## Patch Description

这个patch修复了RISC-V vector状态控制的一个重要bug，确保`riscv_v_ctrl_set()`函数只修改`PR_RISCV_V_VSTATE_CTRL_MASK`范围内的位，而不会意外覆盖其他位。

## 代码修改详情

### 修改文件
- `arch/riscv/kernel/vector.c`

### 具体修改内容

**修改前**:
```c
static inline void riscv_v_ctrl_set(struct task_struct *tsk, int cur, int nxt,
                                   bool inherit)
{
    unsigned long ctrl = 0;
    
    ctrl |= VSTATE_CTRL_MAKE_CUR(cur);
    ctrl |= VSTATE_CTRL_MAKE_NEXT(nxt);
    if (inherit)
        ctrl |= PR_RISCV_V_VSTATE_CTRL_INHERIT;
    tsk->thread.vstate_ctrl = ctrl;  // 直接赋值，可能覆盖其他位
}
```

**修改后**:
```c
static inline void riscv_v_ctrl_set(struct task_struct *tsk, int cur, int nxt,
                                   bool inherit)
{
    unsigned long ctrl = 0;
    
    ctrl |= VSTATE_CTRL_MAKE_CUR(cur);
    ctrl |= VSTATE_CTRL_MAKE_NEXT(nxt);
    if (inherit)
        ctrl |= PR_RISCV_V_VSTATE_CTRL_INHERIT;
    tsk->thread.vstate_ctrl &= ~PR_RISCV_V_VSTATE_CTRL_MASK;  // 先清除相关位
    tsk->thread.vstate_ctrl |= ctrl;                          // 再设置新值
}
```

## 相关常量定义

在`include/uapi/linux/prctl.h`中定义了相关的RISC-V vector控制常量：

```c
#define PR_RISCV_V_SET_CONTROL      69
#define PR_RISCV_V_GET_CONTROL      70
# define PR_RISCV_V_VSTATE_CTRL_DEFAULT     0
# define PR_RISCV_V_VSTATE_CTRL_OFF         1
# define PR_RISCV_V_VSTATE_CTRL_ON          2
# define PR_RISCV_V_VSTATE_CTRL_INHERIT     (1 << 4)
# define PR_RISCV_V_VSTATE_CTRL_CUR_MASK    0x3
# define PR_RISCV_V_VSTATE_CTRL_NEXT_MASK   0xc
# define PR_RISCV_V_VSTATE_CTRL_MASK        0x1f
```

在`arch/riscv/kernel/vector.c`中还定义了相关的宏：

```c
#define VSTATE_CTRL_GET_CUR(x) ((x) & PR_RISCV_V_VSTATE_CTRL_CUR_MASK)
#define VSTATE_CTRL_GET_NEXT(x) (((x) & PR_RISCV_V_VSTATE_CTRL_NEXT_MASK) >> 2)
#define VSTATE_CTRL_MAKE_NEXT(x) (((x) << 2) & PR_RISCV_V_VSTATE_CTRL_NEXT_MASK)
#define VSTATE_CTRL_GET_INHERIT(x) (!!((x) & PR_RISCV_V_VSTATE_CTRL_INHERIT))
```

## 技术原理分析

### 1. Vector状态控制位布局

`PR_RISCV_V_VSTATE_CTRL_MASK` (0x1f) 定义了vector状态控制的有效位范围：
- 位 0-1: 当前状态 (`PR_RISCV_V_VSTATE_CTRL_CUR_MASK` = 0x3)
- 位 2-3: 下一个状态 (`PR_RISCV_V_VSTATE_CTRL_NEXT_MASK` = 0xc)
- 位 4: 继承标志 (`PR_RISCV_V_VSTATE_CTRL_INHERIT` = 0x10)

### 2. 问题根源

原始代码直接使用赋值操作：
```c
tsk->thread.vstate_ctrl = ctrl;
```

这种方式会完全覆盖`vstate_ctrl`字段的所有位，包括那些不应该被修改的位。如果`vstate_ctrl`字段在将来扩展或者被其他代码使用了其他位，这种直接赋值就会导致数据丢失。

### 3. 修复方案

新的代码使用了位掩码操作：
```c
tsk->thread.vstate_ctrl &= ~PR_RISCV_V_VSTATE_CTRL_MASK;  // 清除相关位
tsk->thread.vstate_ctrl |= ctrl;                          // 设置新值
```

这种方式确保：
1. 只清除`PR_RISCV_V_VSTATE_CTRL_MASK`定义的位（位0-4）
2. 保留其他位的原始值
3. 只设置需要修改的位
