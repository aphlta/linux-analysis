## 3. Ztso扩展技术原理

### 3.1 Ztso扩展概述

Ztso (Total Store Ordering) 是RISC-V的一个内存模型扩展：

- **目的**: 提供更强的内存一致性保证
- **模型**: 实现Total Store Ordering内存模型
- **兼容性**: 与x86的TSO内存模型兼容
- **状态**: 已被RISC-V International正式批准

### 3.2 内存模型对比

#### 3.2.1 RISC-V基础内存模型 (RVWMO)
- 弱内存模型 (Weak Memory Ordering)
- 允许更多的内存操作重排序
- 需要显式的fence指令来保证顺序
- 性能优化潜力更大

#### 3.2.2 Ztso内存模型
- 强内存模型 (Strong Memory Ordering)
- 限制内存操作的重排序
- 提供更直观的内存一致性语义
- 简化多线程编程

### 3.3 Ztso的技术特性

1. **Store-to-Load转发**: 保证store操作对后续load操作的可见性
2. **Store顺序**: 保证store操作的全局顺序
3. **Load顺序**: 在某些条件下保证load操作的顺序
4. **原子操作**: 提供更强的原子操作语义

## 4. hwprobe机制分析

### 4.1 hwprobe系统调用

hwprobe是RISC-V特有的系统调用，用于查询硬件特性：

```c
long riscv_hwprobe(struct riscv_hwprobe *pairs, size_t pair_count,
                   size_t cpu_count, unsigned long *cpus, unsigned int flags);
```

### 4.2 工作原理

1. **用户空间调用**: 应用程序调用hwprobe系统调用
2. **内核处理**: 内核检查硬件特性并返回支持的扩展
3. **位掩码返回**: 通过位掩码形式返回支持的ISA扩展
4. **运行时检测**: 允许应用程序在运行时适配不同的硬件特性

### 4.3 EXT_KEY宏机制

`EXT_KEY`宏的作用：
- 检查当前CPU是否支持指定的ISA扩展
- 如果支持，在返回的位掩码中设置对应的位
- 提供统一的扩展检测接口

## 5. 代码修改原理

### 5.1 位掩码分配策略

```c
#define RISCV_HWPROBE_EXT_ZFA           (1ULL << 32)
#define RISCV_HWPROBE_EXT_ZTSO          (1ULL << 33)  // 新增
#define RISCV_HWPROBE_EXT_ZACAS         (1ULL << 34)
```

**分析**:
- 按顺序分配位位置，避免冲突
- 使用64位无符号长整型，支持更多扩展
- 保持与现有扩展的一致性

### 5.2 内核检测逻辑

内核通过以下方式检测Ztso支持：
1. 读取硬件ISA字符串
2. 解析扩展列表
3. 检查Ztso扩展是否存在
4. 设置对应的hwprobe位

### 5.3 用户空间使用

```c
struct riscv_hwprobe pair;
pair.key = RISCV_HWPROBE_KEY_IMA_EXT_0;
riscv_hwprobe(&pair, 1, 0, NULL, 0);

if (pair.value & RISCV_HWPROBE_EXT_ZTSO) {
    // 使用Ztso特性优化的代码路径
} else {
    // 使用通用的代码路径
}
```
