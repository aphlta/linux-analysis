#### 5.6 Steal时间读取
```c
static u64 pv_time_steal_clock(int cpu)
{
    struct sbi_sta_struct *st = per_cpu_ptr(&steal_time, cpu);
    __le32 sequence;
    __le64 steal;

    // 使用序列号确保数据一致性
    do {
        sequence = READ_ONCE(st->sequence);
        virt_rmb();
        steal = READ_ONCE(st->steal);
        virt_rmb();
    } while ((le32_to_cpu(sequence) & 1) ||
         sequence != READ_ONCE(st->sequence));

    return le64_to_cpu(steal);
}
```

#### 5.7 初始化函数
```c
int __init pv_time_init(void)
{
    if (!has_pv_steal_clock())
        return 0;

    // 设置CPU热插拔回调
    ret = cpuhp_setup_state(CPUHP_AP_ONLINE_DYN,
                "riscv/pv_time:online",
                pv_time_cpu_online,
                pv_time_cpu_down_prepare);

    // 更新静态调用
    static_call_update(pv_steal_clock, pv_time_steal_clock);

    // 启用steal time功能
    static_key_slow_inc(&paravirt_steal_enabled);
    if (steal_acc)
        static_key_slow_inc(&paravirt_steal_rq_enabled);

    return 0;
}
```

## 技术原理分析

### 1. Static Call机制

这个补丁大量使用了Linux内核的static call机制:
- **优势**: 相比函数指针调用，static call在运行时开销更低
- **实现**: 通过代码修补技术，将间接调用转换为直接调用
- **用途**: 在paravirt环境中，根据运行环境动态选择合适的实现

### 2. Steal Time概念

**Steal Time**是虚拟化环境中的重要概念:
- **定义**: 虚拟CPU被hypervisor抢占，无法运行guest代码的时间
- **用途**: 帮助guest OS的调度器做出更准确的调度决策
- **实现**: 通过共享内存页面，hypervisor更新steal time信息

### 3. SBI STA扩展

**SBI (Supervisor Binary Interface) STA (Steal Time Accounting)**:
- **目的**: 为RISC-V虚拟化环境提供标准化的steal time接口
- **版本要求**: 需要SBI规范版本2.0或更高
- **功能**: 提供设置共享内存、获取steal time等功能

### 4. 内存一致性保证

代码中使用了多种机制确保数据一致性:
- **序列号机制**: 防止读取过程中数据被修改
- **内存屏障**: `virt_rmb()`确保读取顺序
- **原子操作**: `READ_ONCE()`防止编译器优化
