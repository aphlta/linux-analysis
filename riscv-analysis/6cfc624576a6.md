## 详细代码修改分析

### 1. SBI扩展ID定义

**新增扩展标识符**:
```c
enum sbi_ext_id {
    // ... 现有扩展 ...
    SBI_EXT_DBCN = 0x4442434E,
+   SBI_EXT_STA = 0x535441,     // 新增STA扩展
    
    /* Experimentals extensions must lie within this range */
    SBI_EXT_EXPERIMENTAL_START = 0x08000000,
    // ...
};
```

**扩展ID解析**:
- `0x535441` = "STA" 的ASCII编码
- S = 0x53, T = 0x54, A = 0x41
- 遵循SBI规范的扩展命名约定

### 2. SBI STA功能ID定义

**新增功能枚举**:
```c
/* SBI STA (steal-time accounting) extension */
enum sbi_ext_sta_fid {
    SBI_EXT_STA_STEAL_TIME_SET_SHMEM = 0,
};
```

**功能说明**:
- `SBI_EXT_STA_STEAL_TIME_SET_SHMEM`: 设置steal-time共享内存区域
- 功能ID为0，表示这是STA扩展的第一个（也是目前唯一的）功能

### 3. SBI STA数据结构定义

**共享内存结构体**:
```c
struct sbi_sta_struct {
    __le32 sequence;    // 序列号，用于数据一致性
    __le32 flags;       // 标志位
    __le64 steal;       // steal时间累计值（纳秒）
    u8 preempted;       // 抢占状态标志
    u8 pad[47];         // 填充到64字节对齐
} __packed;
```

**字段详细说明**:
- `sequence`: 32位序列号，用于确保guest读取数据的一致性
  - 奇数表示hypervisor正在更新数据
  - 偶数表示数据稳定，可以安全读取
- `flags`: 32位标志位，当前未使用，保留为0
- `steal`: 64位steal时间累计值，以纳秒为单位
- `preempted`: 8位抢占状态，0表示未被抢占，1表示被抢占
- `pad[47]`: 47字节填充，确保整个结构体为64字节

**设计考虑**:
- 使用`__le32`和`__le64`确保小端字节序兼容性
- 64字节对齐优化缓存性能
- `__packed`属性确保结构体紧密排列

### 4. 共享内存控制宏定义

**禁用宏定义**:
```c
#define SBI_STA_SHMEM_DISABLE    -1
```

**用途**:
- 当guest调用`SBI_EXT_STA_STEAL_TIME_SET_SHMEM`时
- 传递此值可以禁用steal-time统计功能
- 相当于取消共享内存区域的设置

## 技术原理分析

### 1. Steal-Time概念

**定义**: Steal-time是指虚拟CPU应该运行但实际被hypervisor调度给其他任务的时间。

**重要性**:
- 帮助guest OS准确计算CPU使用率
- 提供虚拟化环境的性能分析数据
- 支持更精确的时间管理和调度决策

### 2. SBI扩展机制

**SBI (Supervisor Binary Interface)**:
- RISC-V架构的标准化接口
- 定义了操作系统与固件/hypervisor之间的通信协议
- 通过`ecall`指令调用

**扩展机制优势**:
- 标准化：确保不同实现之间的兼容性
- 可扩展：支持新功能的动态添加
- 高效：避免复杂的设备模拟开销

### 3. 共享内存机制

**设计原理**:
- Guest和hypervisor共享同一块内存区域
- Hypervisor更新steal-time数据
- Guest读取数据进行时间统计

**一致性保证**:
- 使用序列号机制确保数据一致性
- Guest读取时检查序列号的奇偶性
- 避免读取到部分更新的数据

**内存布局**:
```
+0x00: sequence (4 bytes)
+0x04: flags    (4 bytes)
+0x08: steal    (8 bytes)
+0x10: preempted(1 byte)
+0x11: pad      (47 bytes)
总计: 64 bytes
```
