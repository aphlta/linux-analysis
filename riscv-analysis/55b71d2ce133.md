## 修改概述

这个patch将RISC-V架构中禁用链接器松弛(linker relaxation)的逻辑从Makefile提升到Kconfig配置系统中，使得配置决策可以在配置时而非编译时做出。

## 详细修改内容

### 1. arch/riscv/Kconfig 修改

**新增配置选项:**
```kconfig
config RISCV_USE_LINKER_RELAXATION
       def_bool y
       # https://github.com/llvm/llvm-project/commit/6611d58f5bbcbec77262d392e2923e1d680f6985
       depends on !LD_IS_LLD || LLD_VERSION >= 150000
```

**关键特性:**
- `def_bool y`: 默认启用链接器松弛
- 依赖条件: 当使用LLD链接器时，要求版本 >= 15.0.0
- 引用了LLVM项目的具体commit，说明了版本要求的技术背景

### 2. arch/riscv/Makefile 修改

**修改前的逻辑:**
```makefile
ifeq ($(CONFIG_LD_IS_LLD),y)
ifeq ($(call test-lt, $(CONFIG_LLD_VERSION), 150000),y)
        KBUILD_CFLAGS += -mno-relax
        KBUILD_AFLAGS += -mno-relax
ifndef CONFIG_AS_IS_LLVM
        KBUILD_CFLAGS += -Wa,-mno-relax
        KBUILD_AFLAGS += -Wa,-mno-relax
endif
endif
endif
```

**修改后的逻辑:**
```makefile
ifndef CONFIG_RISCV_USE_LINKER_RELAXATION
        KBUILD_CFLAGS += -mno-relax
        KBUILD_AFLAGS += -mno-relax
ifndef CONFIG_AS_IS_LLVM
        KBUILD_CFLAGS += -Wa,-mno-relax
        KBUILD_AFLAGS += -Wa,-mno-relax
endif
endif
```

## 技术原理分析

### 1. 链接器松弛(Linker Relaxation)技术

链接器松弛是一种优化技术，允许链接器在链接时修改指令序列以提高代码效率：

- **目的**: 优化跳转指令、地址计算等，减少代码大小和提高性能
- **RISC-V特性**: RISC-V架构特别依赖链接器松弛来优化地址计算
- **实现**: 编译器生成保守的指令序列，链接器根据最终布局进行优化

### 2. LLVM LLD版本兼容性问题

**问题背景:**
- LLD 15.0.0之前的版本在RISC-V链接器松弛实现上存在bug
- 这些bug可能导致链接错误或运行时问题
- 特别是与DWARF5调试信息结合使用时会出现问题

**解决方案:**
- 检测LLD版本，低于15.0.0时禁用链接器松弛
- 使用`-mno-relax`编译选项禁用松弛优化
- 对于非LLVM汇编器，还需要传递`-Wa,-mno-relax`参数

### 3. 配置系统重构的优势

**从Makefile到Kconfig的迁移带来以下好处:**

1. **配置时决策**: 在内核配置阶段就确定是否使用链接器松弛
2. **依赖管理**: 其他配置选项可以依赖`RISCV_USE_LINKER_RELAXATION`
3. **可见性**: 用户可以在配置界面看到这个选项
4. **扩展性**: 为后续相关功能(如DWARF5支持)提供基础

## 技术细节

### 编译选项说明

- `-mno-relax`: 告诉编译器不生成需要链接器松弛的指令序列
- `-Wa,-mno-relax`: 传递给汇编器的选项，禁用汇编级别的松弛
- `--no-relax-gp`: 链接器选项，禁用全局指针相关的松弛(用于Shadow Call Stack)

### 版本检测机制

```makefile
# 旧的检测方式
ifeq ($(call test-lt, $(CONFIG_LLD_VERSION), 150000),y)

# 新的配置方式
depends on !LD_IS_LLD || LLD_VERSION >= 150000
```

新方式更清晰，且在配置阶段就完成检测。
