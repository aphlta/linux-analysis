# Patch Analysis: d6c78f1ca3e8

**标题:** riscv: vector: do not pass task_struct into riscv_v_vstate_{save,restore}()

## 修改概述

这个patch重构了RISC-V Vector扩展中的状态保存和恢复函数，将`riscv_v_vstate_save()`和`riscv_v_vstate_restore()`函数的参数从接受`task_struct`指针改为直接接受`struct __riscv_v_ext_state`指针。

## 详细修改内容

### 1. 函数签名变更

**修改前:**
```c
static inline void riscv_v_vstate_save(struct task_struct *task, struct pt_regs *regs)
static inline void riscv_v_vstate_restore(struct task_struct *task, struct pt_regs *regs)
```

**修改后:**
```c
static inline void riscv_v_vstate_save(struct __riscv_v_ext_state *vstate, struct pt_regs *regs)
static inline void riscv_v_vstate_restore(struct __riscv_v_ext_state *vstate, struct pt_regs *regs)
```

### 2. 函数实现简化

**修改前的实现:**
```c
static inline void riscv_v_vstate_save(struct task_struct *task, struct pt_regs *regs)
{
    if ((regs->status & SR_VS) == SR_VS_DIRTY) {
        struct __riscv_v_ext_state *vstate = &task->thread.vstate;
        __riscv_v_vstate_save(vstate, vstate->datap);
        __riscv_v_vstate_clean(regs);
    }
}
```

**修改后的实现:**
```c
static inline void riscv_v_vstate_save(struct __riscv_v_ext_state *vstate, struct pt_regs *regs)
{
    if (__riscv_v_vstate_check(regs->status, DIRTY)) {
        __riscv_v_vstate_save(vstate, vstate->datap);
        __riscv_v_vstate_clean(regs);
    }
}
```

### 3. 调用点更新

所有调用这两个函数的地方都需要更新，传递`&current->thread.vstate`而不是`current`:

- **arch/riscv/include/asm/entry-common.h**
- **arch/riscv/include/asm/vector.h** (在`__switch_to_vector`函数中)
- **arch/riscv/kernel/kernel_mode_vector.c**
- **arch/riscv/kernel/ptrace.c**
- **arch/riscv/kernel/signal.c**

### 4. 宏定义更新

在`CONFIG_RISCV_ISA_V`未定义时的空宏定义也相应更新:
```c
// 修改前
#define riscv_v_vstate_save(task, regs)     do {} while (0)
#define riscv_v_vstate_restore(task, regs)  do {} while (0)

// 修改后
#define riscv_v_vstate_save(vstate, regs)   do {} while (0)
#define riscv_v_vstate_restore(vstate, regs) do {} while (0)
```

## 修改原理分析

### 1. 解耦设计

原来的设计中，`riscv_v_vstate_save()`和`riscv_v_vstate_restore()`函数需要知道完整的`task_struct`结构，然后从中提取`thread.vstate`。新的设计直接传递所需的`vstate`指针，实现了更好的解耦。

### 2. 提高复用性

这个修改的主要动机是为了支持即将引入的kernel-mode Vector功能。在内核模式下使用Vector时，可能需要操作不同的vstate结构，而不仅仅是当前任务的vstate。通过直接传递vstate指针，这些函数可以操作任意的Vector状态结构。

### 3. 简化函数逻辑

函数不再需要从task_struct中提取vstate，减少了一层间接访问，使代码更加直接和高效。

## 技术影响
