## 问题描述

这个patch修复了RISC-V CBO (Cache Block Operations) 测试中的内联汇编约束问题。原始代码在没有优化的编译条件下会导致编译失败，因为编译器无法识别传递给内联汇编的操作数是常量。

### 错误现象

当使用 `-O0` 编译选项时，编译器会报错：
```
Error: 'i' constraint expects a constant operand
```

### 根本原因

1. **内联汇编约束问题**: 'i' 约束要求操作数必须是编译时常量
2. **函数参数传递**: 将 `fn` 作为函数参数传递，编译器在无优化时无法确定其为常量
3. **局部变量使用**: 使用局部变量 `insn` 存储 `MK_CBO(fn)` 的结果，进一步模糊了常量性质

## 代码修改详细分析

### 修改前的代码

```c
static void cbo_insn(char *base, int fn)
{
    uint32_t insn = MK_CBO(fn);

    asm volatile(
    "mv     a0, %0\n"
    "li     a1, %1\n"
    ".4byte %2\n"
    : : "r" (base), "i" (fn), "i" (insn) : "a0", "a1", "memory");
}
```

### 修改后的代码

```c
#define cbo_insn(base, fn)                          \
({                                                  \
    asm volatile(                                \
    "mv     a0, %0\n"                            \
    "li     a1, %1\n"                            \
    ".4byte %2\n"                                \
    : : "r" (base), "i" (fn), "i" (MK_CBO(fn)) : "a0", "a1", "memory");   \
})
```

### 关键技术变化

1. **函数改为宏**: 将 `cbo_insn` 从函数改为宏定义
2. **直接使用常量**: 直接在内联汇编中使用 `MK_CBO(fn)`，而不是通过局部变量
3. **保持常量性质**: 确保编译器能够识别 `fn` 和 `MK_CBO(fn)` 都是编译时常量

## MK_CBO宏分析

```c
#define MK_CBO(fn) le32_bswap((uint32_t)(fn) << 20 | 10 << 15 | 2 << 12 | 0 << 7 | 15)
```

### le32_bswap定义

```c
#if __BYTE_ORDER == __BIG_ENDIAN
# define le32_bswap(_x)                \
    ((((_x) & 0x000000ffU) << 24) |    \
     (((_x) & 0x0000ff00U) <<  8) |    \
     (((_x) & 0x00ff0000U) >>  8) |    \
     (((_x) & 0xff000000U) >> 24))
#else
# define le32_bswap(_x) (_x)
#endif
```

### CBO指令编码分析

`MK_CBO(fn)` 宏构造RISC-V CBO指令的32位编码：

- `fn << 20`: 功能码位于[24:20]位
- `10 << 15`: rs2字段，值为10
- `2 << 12`: funct3字段，值为2  
- `0 << 7`: rs1字段，值为0
- `15`: opcode字段，值为15

这对应RISC-V CBO指令的标准编码格式。

## 编译器约束详解

### 'i' 约束的要求

- **定义**: 'i' 约束要求操作数必须是立即数（编译时常量）
- **用途**: 用于需要在汇编时确定值的指令操作数
- **限制**: 不能是运行时变量或通过函数参数传递的值

### 优化级别的影响

- **-O2及以上**: 编译器会进行内联和常量传播，能够识别常量
- **-O0**: 编译器不进行优化，无法识别通过函数参数传递的常量

## 相关CBO操作

修改后的代码支持以下CBO操作：

```c
static void cbo_inval(char *base) { cbo_insn(base, 0); }  // Cache Block Invalidate
static void cbo_clean(char *base) { cbo_insn(base, 1); }  // Cache Block Clean
static void cbo_flush(char *base) { cbo_insn(base, 2); }  // Cache Block Flush
static void cbo_zero(char *base)  { cbo_insn(base, 4); }  // Cache Block Zero
```

## 测试框架集成

这些CBO指令用于测试RISC-V硬件探测功能：

1. **权限检查**: 测试用户态是否能执行特权CBO指令
2. **异常处理**: 通过SIGILL信号处理器捕获非法指令异常
3. **硬件能力探测**: 验证hwprobe系统调用返回的CBO支持信息

## 最佳实践总结

1. **内联汇编约束**: 使用 'i' 约束时确保操作数在所有编译条件下都是常量
2. **宏vs函数**: 对于需要编译时常量的场景，优先使用宏而不是函数
3. **编译器优化**: 不要依赖编译器优化来满足汇编约束要求
4. **测试覆盖**: 在不同优化级别下测试代码以发现潜在问题
