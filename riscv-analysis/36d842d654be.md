## 问题背景

### 1. 参数命名混淆问题

hwprobe系统调用中与'cpus'参数关联的"count"参数实际上是'cpus'的字节大小，但原来命名为'cpu_count'可能会误导用户认为它是CPU的数量，而不是字节大小。这种混淆特别容易发生，因为：

1. **CPU_SET(3)文档影响**: 'cpus'参数被文档定义为由CPU_SET(3)定义，而CPU_SET(3)也文档化了一个CPU_COUNT()宏（集合中CPU的数量）
2. **语义歧义**: 'cpu_count'这个名称自然让人联想到CPU数量而非字节大小
3. **标准化需求**: CPU_SET(3)使用'setsize'来指代cpu集合的大小

### 2. hwprobe系统调用简介

RISC-V hwprobe是一个硬件探测接口，基于单个系统调用实现：

```c
struct riscv_hwprobe {
    __s64 key;
    __u64 value;
};

long sys_riscv_hwprobe(struct riscv_hwprobe *pairs, size_t pair_count,
                       size_t cpusetsize, cpu_set_t *cpus,
                       unsigned int flags);
```

该系统调用允许用户空间查询RISC-V硬件特性，包括：
- 供应商ID (mvendorid)
- 架构ID (marchid) 
- 实现ID (mimpid)
- ISA扩展支持情况
- 缓存块大小等

## 代码修改原理分析

### 1. 参数语义澄清

#### 1.1 原始问题

```c
// 容易误解的原始定义
long sys_riscv_hwprobe(struct riscv_hwprobe *pairs, size_t pair_count,
                       size_t cpu_count,    // 误导性命名
                       cpu_set_t *cpus, unsigned int flags);
```

用户可能错误理解：
- `cpu_count` = CPU数量
- 实际上：`cpu_count` = CPU集合的字节大小

#### 1.2 澄清后的定义

```c
// 清晰的新定义
long sys_riscv_hwprobe(struct riscv_hwprobe *pairs, size_t pair_count,
                       size_t cpusetsize,   // 明确表示字节大小
                       cpu_set_t *cpus, unsigned int flags);
```

### 2. 与标准库的一致性

#### 2.1 CPU_SET(3)标准

CPU_SET(3)库函数使用以下约定：
- `setsize`: CPU集合的字节大小
- `CPU_COUNT()`: 计算集合中CPU数量的宏
- `CPU_SETSIZE`: 默认CPU集合大小

#### 2.2 对齐标准

通过使用`cpusetsize`，hwprobe系统调用与CPU_SET(3)标准保持一致：

```c
// CPU_SET(3)风格的函数签名
int sched_setaffinity(pid_t pid, size_t cpusetsize, const cpu_set_t *mask);
int sched_getaffinity(pid_t pid, size_t cpusetsize, cpu_set_t *mask);

// 现在hwprobe也遵循相同模式
long sys_riscv_hwprobe(struct riscv_hwprobe *pairs, size_t pair_count,
                       size_t cpusetsize, cpu_set_t *cpus, unsigned int flags);
```

### 3. 系统调用实现机制

#### 3.1 VDSO优化

hwprobe系统调用实现了VDSO（Virtual Dynamic Shared Object）优化：

```c
// VDSO实现路径
__vdso_riscv_hwprobe() -> riscv_vdso_get_values() -> 直接返回缓存值

// 系统调用路径
__vdso_riscv_hwprobe() -> riscv_hwprobe() -> 内核系统调用
```

**优化策略**:
- 对于"所有CPU"查询，直接从VDSO数据页返回
- 对于复杂查询，回退到系统调用
- 减少用户态-内核态切换开销

#### 3.2 CPU集合处理

```c
// cpusetsize参数的使用
static int riscv_vdso_get_cpus(struct riscv_hwprobe *pairs, size_t pair_count,
                               size_t cpusetsize, unsigned long *cpus,
                               unsigned int flags)
{
    unsigned char *c = (unsigned char *)cpus;
    
    // 遍历cpusetsize字节
    for (i = 0; i < cpusetsize; i++) {
        if (c[i]) {
            empty_cpus = false;
            break;
        }
    }
}
```
